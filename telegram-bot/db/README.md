# Database Configuration

## Schema Definition

The database schema is defined through **SQLAlchemy models** (`models.py`), the
single source of truth. `db/schema.sql` used to sit alongside them as a "reference"
copy; it was deleted because the two drifted apart. The live database had been
built from `schema.sql` and carried 23 indexes and 9 `jsonb` columns the models
never declared, so an autogenerated migration would have dropped them.

- **Source of truth**: [models.py](models.py) — SQLAlchemy ORM models
- **Authoritative DDL**: [migrations/versions/](migrations/) — Alembic revisions

## Initialization

Migrations run automatically at startup (`db/migrate.py`), so a normal deploy
needs no manual step.

- A **fresh** database has every migration applied in order.
- A database predating Alembic is **stamped** with the baseline revision —
  recorded as already-current rather than re-executed — then upgraded. Adoption
  cannot touch existing data.

`init_db()` in `connection.py` still exists for tests and tooling that want a
throwaway schema, but it is not used at startup: `create_all()` only creates
*missing tables* and silently ignores columns added to existing ones.

## Schema Changes

1. **Update the model** in `models.py`
2. **Generate a migration**: `alembic revision --autogenerate -m "what changed"`
3. **Review the generated file** — autogenerate is a first draft, not a result
4. Restart, or run `alembic upgrade head`

Before adopting an environment that predates Alembic, confirm its schema
actually matches the models:

```bash
python -m scripts.check_schema_drift
```

Exit code 0 is clean; 1 lists the differences; 2 means the check could not run.

## Directory Contents

- `connection.py` - Async database connection and session helpers
- `models.py` - SQLAlchemy ORM models (schema source of truth)
- `migrate.py` - Migration runner and drift detection
- `migrations/` - Alembic environment and revisions
- `url.py` - Database URL normalization (async driver selection)
- `users.py` - User-related database operations
- `errors.py` - Database error definitions

## Database URL Format

PostgreSQL with an async driver:

```
postgresql+asyncpg://user:password@localhost:5432/database   # Python < 3.14
postgresql+psycopg://user:password@localhost:5432/database   # Python >= 3.14
```

A bare `postgresql://` URL is normalized automatically to whichever async
driver is installed.

Set via environment variable or `.env`:

```
DB_URL=postgresql+asyncpg://coord_user:coord_pass@localhost:5432/coord_db
```

## Development

Create a PostgreSQL docker container:

```bash
bash scripts/setup_db.sh    # or ./resume.sh from the project root
```

Check connection:

```bash
python main.py   # waits for the database, then migrates
```
